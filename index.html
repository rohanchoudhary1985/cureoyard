This page is clay, by the way — .

Mass software is average software.

Every app you use was flattened for a billion people. The feature you reach for daily sits three menus deep; the one you never touch owns your home screen. The run tracker assumes you race. The budget app assumes you invest. You don't.

Software ships as a finished thing — take it or leave it. We think an app should be a starting point, not a verdict.

Software you can mold like clay.

On CureoYard, an app isn't a sealed product — it's a base shape. Move what you use. Remove what you don't. Add the view, the automation, the field that only makes sense for your life.

Reshape it by describing the change in plain words, or go deeper with code. Guardrails handle the rest: your data stays yours, your version stays compatible, and nothing you mold can break the core.

Your app ends up fitting you the way your handwriting does — and it keeps evolving as you do.

How the yard works.

1

Creators publish a base app

The starting shape: core logic, data model, and the guardrails that define what can safely change.

2

People mold their own version

Rearrange, extend, automate. In plain language, with building blocks, or with code — each person's copy becomes their own.

3

The best versions flow back

Great remixes return to the yard for others to adopt and build on. Creators learn from them. Apps evolve for everyone.

Every user becomes a contributor.

GitHub turned code into something developers shape together, fork by fork. The same shift is coming for the apps everyone else lives in — and it needs a home.

That home is the yard: a place where forking an app is as ordinary as customizing a phone wallpaper, where guardrails do the work of code review, and where a great idea from one user can reach millions.

The GitHub of the consumer era.
